5.1 Introduction to React

Pages 93

What is React?

A JavaScript library from Meta for building user interfaces out of small, reusable pieces called components. It uses a virtual DOM, so it updates only the parts of the page that changed.

Setting up the environment

Install Node.js (it includes npm), then create a project:

node -v
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev

Folder structure

  • node_modules/ installed packages
  • public/ static files
  • src/ your code: main.jsx (entry point), App.jsx (root component)
  • package.json dependencies and scripts
  • index.html the single page that React mounts into

5.2 Introduction to JSX

Pages 94 to 95

JSX is HTML-like syntax inside JavaScript. A build tool turns it into React.createElement() calls.

Expressions

Put any JavaScript expression inside curly braces.

const name = "Asha";
const el = <h1>Hello, {name.toUpperCase()}! 2+2 = {2 + 2}</h1>;

Attributes

Use camelCase names: className instead of class, htmlFor instead of for. Strings use quotes, values use braces.

<img src={user.photo} className="avatar" alt="profile" />

Children

Elements can nest. A JSX expression must return one parent, so wrap siblings in a <div> or a fragment <>...</>.

Rendering elements

import { createRoot } from "react-dom/client";
createRoot(document.getElementById("root")).render(<App />);

5.3 Components

Pages 96 to 98

A component is a JavaScript function that returns JSX. Its name must start with a capital letter.

Create your first component

function Welcome() {
  return <h2>Welcome to React</h2>;
}

Composing components

Build big UIs by placing components inside other components.

function App() {
  return (
    <>
      <Header />
      <Welcome />
      <Footer />
    </>
  );
}

5.4 Props and State

Pages 98 to 99

Props

Inputs passed from parent to child. They are read-only.

State

Data a component owns and can change. Changing state re-renders the component. Use the useState hook.

Communication using props

Data flows down through props. To send data up, the parent passes a function as a prop and the child calls it.

function Greeting({ name }) {            // props
  return <p>Hi {name}</p>;
}
function Counter() {
  const [count, setCount] = useState(0);   // state
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

5.4.4 Component lifecycle methods

Pages 101 to 103

Every component goes through phases. Pick one:

// Function component equivalent
useEffect(() => {
  console.log("mounted");           // componentDidMount
  return () => console.log("bye");  // componentWillUnmount
}, []);

useEffect(() => { /* runs when count changes */ }, [count]);  // componentDidUpdate

5.5 Handling events

Page 103

Events use camelCase names and you pass a function, not a string. Call e.preventDefault() to stop default behaviour such as form submission.

function Save() {
  function handleClick(e) { e.preventDefault(); alert("Saved"); }
  return <button onClick={handleClick}>Save</button>;
}

5.6 Conditional rendering

Page 104

Show different UI depending on a condition, using plain JavaScript.

{isLoggedIn ? <Dashboard /> : <Login />}   // ternary
{unread > 0 && <Badge n={unread} />}         // logical AND
if (loading) return <Spinner />;               // early return

5.7 Lists and keys

Page 104

Use map() to turn an array into elements. Each item needs a unique, stable key so React can track it. Prefer an id over the array index.

<ul>
  {todos.map(t => <li key={t.id}>{t.text}</li>)}
</ul>

5.8 Forms

Pages 105 to 109

HTML tags in forms

<input>, <select>, <textarea> and <input type="file"> all work in JSX. In React, textarea and select use a value prop.

Controlled components

React state is the single source of truth for the input's value.

const [name, setName] = useState("");
<input value={name} onChange={e => setName(e.target.value)} />

Uncontrolled components

The DOM keeps the value, and you read it with a ref when needed. Useful for file inputs and simple forms.

const ref = useRef();
<input ref={ref} />
<button onClick={() => alert(ref.current.value)}>Read</button>

5.9 Lifting state up

Page 109

When two components need the same data, move the state to their closest common parent and pass it down as props, along with a setter function.

function Parent() {
  const [temp, setTemp] = useState(0);
  return (
    <>
      <Input value={temp} onChange={setTemp} />
      <Display value={temp} />
    </>
  );
}

5.10 Testing single page applications

Page 110

Common tools: Jest or Vitest as the test runner and React Testing Library to test what users see.

import { render, screen } from "@testing-library/react";
test("shows welcome text", () => {
  render(<Welcome />);
  expect(screen.getByText(/welcome/i)).toBeInTheDocument();
});

Important questions

Tap a question to reveal a short answer

What is the difference between props and state?Props are passed in from a parent and are read-only. State is owned by the component and can change, causing a re-render.
What is the virtual DOM?A lightweight copy of the real DOM. React compares the old and new copies and updates only what changed.
Why are keys needed in lists?Keys let React identify which items were added, removed or moved, so it updates efficiently and keeps state correct.
Controlled vs uncontrolled components?Controlled: React state holds the input value. Uncontrolled: the DOM holds it and you read it through a ref.
Name the lifecycle phases.Initialization, mounting, updating, unmounting, plus error handling.
What does "lifting state up" mean?Moving shared state to the nearest common parent so sibling components stay in sync.
